AI心理医生Agent技术路线文档
1. 项目概述
本Agent旨在通过苏格拉底式提问、乔哈里视窗、焦点解决短期治疗等心理学理论，引导用户进行自我探索和需求梳理。Agent不直接给出建议，而是通过结构化提问帮助用户澄清内心真实想法，最终形成个性化的分析报告与行动建议。

核心功能：

多轮对话式提问（分批或一次性）

基于RAG的心理学知识检索与融合

用户画像与长期记忆管理

安全边界与危机干预

多Agent协作（提问Agent、分析Agent、安全Agent等）

可扩展的架构设计，支持高并发与低延迟

3. 系统架构
采用微服务架构，将不同职责拆分为独立服务，通过消息队列和API网关通信。

text
[用户] ↔ [API网关] ↔ [对话管理服务]
                          ↕
              [意图识别与路由] → [提问Agent]
                          ↕         ↕
              [记忆管理服务] ← [分析Agent]
                          ↕
              [RAG检索服务] → [安全Agent]
                          ↕
              [知识库更新服务]
核心组件说明：

API网关：负责鉴权、限流、请求路由。

对话管理服务：维护会话状态，编排多Agent协作流程。

意图识别与路由：判断用户输入类型（如提问、回答、紧急求助），决定调用哪个Agent。

提问Agent：根据用户当前状态和历史回答生成下一个提问，或一次性生成10个问题。

分析Agent：在用户回答完毕后，综合分析所有回答，生成潜意识诉求报告与建议。

安全Agent：实时监测对话内容，识别危机信号（自杀、自伤、暴力等），触发干预流程。

记忆管理服务：管理短期记忆（当前会话）和长期记忆（跨会话用户画像），处理记忆冲突。

RAG检索服务：检索心理学理论、案例、引导问题模板，为提问Agent提供支撑。

知识库更新服务：定期更新知识库，评估检索效果，优化索引。

4. 核心流程设计
4.1 主交互流程（苏格拉底式引导）
用户输入初始困惑（例如：“我该不该辞职创业？”）。

对话管理服务接收输入，调用意图识别，判断为“寻求引导”。

调用提问Agent，结合用户画像和RAG检索到的相关理论，生成第一批问题（可一次生成10个或分批）。

用户逐条回答（或一次性提交所有回答）。

回答过程中，记忆管理服务实时更新短期记忆（用户回答内容）和用户画像（价值观、恐惧、偏好等）。

全部回答完成后，调用分析Agent，汇总所有回答，进行深度分析，输出报告。

安全Agent全程监控，若发现危机信号立即干预。

报告通过API返回给用户，并存入长期记忆。

4.2 多轮提问模式（可配置）
一次性模式：一次性生成10个问题，用户一次性回答。

渐进模式：每次生成1个问题，根据用户回答动态调整下一个问题（需多次调用LLM，更灵活）。

5. 关键技术难点与解决方案
5.1 并发处理
问题：高并发下LLM API调用延迟高，系统资源耗尽。

解决方案：

使用FastAPI + asyncio异步非阻塞IO，提高单机吞吐。

对LLM API调用采用连接池和请求队列，限制并发数（如每模型最大并发10）。

无状态服务设计，水平扩展对话管理服务实例。

使用Redis作为分布式会话存储，支持多实例共享会话状态。

对耗时操作（如RAG检索、分析生成）使用消息队列异步处理，返回任务ID，前端轮询或WebSocket推送。

5.2 提示词截断与上下文窗口管理
问题：用户回答可能很长，加上历史对话和知识注入，容易超出模型上下文窗口。

解决方案：

动态窗口管理：保留最近N轮对话（可配置），更早对话进行摘要压缩。

分层记忆：

短期记忆（Redis）：当前会话完整对话。

中期记忆（向量库）：提取的对话要点、用户回答的事实性信息。

长期记忆（PostgreSQL）：用户画像、历史分析报告摘要。

提示词模板引擎：将固定指令、动态用户信息、检索结果分开管理，动态拼接，避免冗余。

检索内容精炼：RAG检索到的文档片段经过摘要后只保留关键句子。

5.3 幻觉控制
问题：LLM生成内容可能偏离心理学理论或产生不准确建议。

解决方案：

RAG约束：所有生成内容必须基于检索到的权威心理学资料，在提示词中明确要求“仅基于提供资料回答，不得编造”。

引用机制：在分析报告中标注引用来源（如“根据《焦点解决短期治疗》...”）。

后验证：使用辅助LLM检查生成内容是否与检索资料一致，不一致则重新生成。

人工反馈循环：收集用户对报告准确性的评分，用于微调或调整RAG权重。

5.4 准确性与安全性边界
问题：心理领域高度敏感，错误建议可能造成伤害。

解决方案：

安全分级：将用户问题分为普通、敏感、危机三级。危机级（如自杀倾向）立即转人工或提供紧急热线，不继续AI对话。

内容过滤：使用OpenAI Moderation API或自训练分类器，过滤仇恨、暴力、色情等内容。

专业边界：在系统提示词中反复强调“本AI不能替代专业心理咨询，仅提供自我探索引导，如遇严重心理问题请寻求专业帮助”。

免责声明：每次响应末尾附上简短声明。

定期审计：由心理学专家审核生成质量，更新安全规则。

5.5 多Agent协作
问题：提问Agent和分析Agent的职责划分与数据同步。

解决方案：

使用消息队列解耦，各Agent独立部署，通过事件驱动协作。

事件类型：question_requested、answer_received、analysis_requested等。

对话管理服务作为编排器，维护状态机，决定何时调用哪个Agent。

记忆管理服务作为共享数据层，各Agent通过API读写记忆，避免直接共享内存。

使用Saga模式处理跨Agent事务（如一次提问生成失败，需要重试或降级）。

5.6 记忆冲突
问题：用户在不同时间表达过矛盾的观点，长期记忆如何更新？

解决方案：

冲突检测：当新回答与旧画像矛盾时（如用户以前说“重视稳定”，现在说“想冒险”），触发冲突处理。

解决策略：

时间衰减：新信息权重更高，但保留旧信息作为上下文。

显式询问：在分析报告中指出矛盾点，邀请用户澄清（符合苏格拉底式引导）。

分层存储：将记忆分为“当前状态”和“历史轨迹”，分析时同时参考变化趋势。

技术实现：使用向量相似度检测新旧记忆的语义冲突，结合LLM判断是否冲突。

5.7 检索与重排可靠性
问题：向量检索分数与BM25分数相近，Reranker返回结果差异小，导致最终检索结果不稳定。

解决方案：

混合检索：同时使用向量检索（语义相似）和关键词检索（BM25），分别取Top-K，合并去重。

多路召回：使用不同向量模型（如BGE-M3、E5）各召回一批，增加多样性。

重排序：使用交叉编码器（如Cohere Rerank、bge-reranker）对合并结果重新打分。

分数校准：对向量分数和BM25分数进行归一化（如Min-Max或sigmoid），加权融合。

LLM作为终审：当Top结果分数接近时，调用轻量LLM对候选片段进行相关性判断（0-3分），选取最高分。

缓存检索结果：对高频查询缓存结果，减少重复计算。

评估驱动优化：定期用标注数据评估检索命中率，调整融合权重。

5.8 调用失败处理
问题：LLM API超时、限流、返回错误。

解决方案：

重试策略：指数退避重试（如3次），对可重试错误（429、500、网络超时）自动重试。

降级机制：主模型失败时切换备用模型（如GPT-4o失败用Claude或本地模型）。

缓存兜底：对于常见问题，缓存标准提问模板，API失败时返回预生成内容。

异步任务队列：长耗时操作放入队列，失败自动重试或通知用户。

5.9 响应延迟优化
问题：LLM生成10个问题可能需要10-20秒，用户等待焦虑。

解决方案：

流式输出：使用SSE或WebSocket，让用户看到问题逐字生成。

预生成：对于常见困惑类型（如职业选择、人际关系），预生成提问模板，直接返回或微调。

缓存常见回答：对用户回答的常见模式，缓存分析报告草稿。

异步分批：先返回前3个问题，后台生成剩余7个，用户回答前3个时后7个已就绪。

边缘计算：使用CDN加速静态资源，API就近部署。

5.10 RAG效果评估
问题：如何衡量检索质量，确保知识注入有效。

解决方案：

构建评估集：由心理学专家标注100-500个典型查询及理想检索文档。

离线指标：

Recall@k：理想文档在Top-K中的比例。

MRR（平均倒数排名）。

NDCG@k。

在线指标：

用户对生成报告的相关性评分（1-5星）。

分析报告中引用与用户问题的匹配度（LLM辅助判断）。

A/B测试：不同检索策略（如仅向量 vs 混合）随机分配给用户，比较用户满意度。

持续更新：根据评估结果调整嵌入模型、重排器参数或知识库内容。

6. 数据模型设计
6.1 用户表（PostgreSQL）
字段	类型	说明
user_id	UUID	主键
created_at	TIMESTAMP	注册时间
last_seen	TIMESTAMP	最近活跃
risk_level	INT	风险等级（0正常，1关注，2高危）
consent_given	BOOLEAN	是否同意数据使用
anonymized	BOOLEAN	是否匿名化存储
6.2 会话表
字段	类型	说明
session_id	UUID	主键
user_id	UUID	外键
start_time	TIMESTAMP	会话开始
end_time	TIMESTAMP	会话结束
status	ENUM	active, completed, aborted
summary	TEXT	会话摘要（用于长期记忆）
6.3 消息表
字段	类型	说明
message_id	UUID	主键
session_id	UUID	外键
role	ENUM	user, assistant, system
content	TEXT	消息内容
created_at	TIMESTAMP	时间
metadata	JSONB	附加信息（如提问类型、引用等）
6.4 长期记忆表（用户画像）
字段	类型	说明
memory_id	UUID	主键
user_id	UUID	外键
category	VARCHAR	如价值观、恐惧、偏好
content	TEXT	记忆内容
confidence	FLOAT	置信度
created_at	TIMESTAMP	创建时间
updated_at	TIMESTAMP	最后更新时间
source_session	UUID	来源会话
6.5 知识库（向量数据库）
存储心理学理论、案例、引导问题模板，每条记录包含：

doc_id

text（分块内容）

embedding（向量）

metadata（来源、标签等）

7. 部署与运维
容器化：所有服务打包Docker镜像。

编排：使用Kubernetes管理，配置HPA自动扩缩容（基于CPU和请求队列长度）。

日志：使用ELK（Elasticsearch, Logstash, Kibana）或Loki收集日志，Sentry捕获异常。

监控：Prometheus收集指标（请求数、延迟、错误率、LLM调用次数、缓存命中率），Grafana展示。

告警：当错误率超过阈值、响应延迟突增、安全Agent触发危机干预时发送告警。

8. 安全与隐私
数据加密：传输使用TLS，存储使用AES-256。

用户同意：首次使用时明确告知数据用途，获得同意。

匿名化：分析报告和记忆中去除个人身份信息。

访问控制：内部服务通过API密钥或JWT鉴权。

合规：遵守GDPR、HIPAA（如涉及医疗数据）等法规，提供数据导出和删除接口。

10. 总结
本技术路线覆盖了构建一个基于苏格拉底提问的AI心理医生Agent所需的核心组件与关键难点解决方案。通过微服务架构、RAG增强、多Agent协作和鲁棒的工程实践，可以支撑高并发、低延迟、安全可靠的线上服务。后续可根据此文档，利用AI工具生成各部分代码骨架，逐步实现整个系统。
